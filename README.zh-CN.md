# 拖拽导入

**思源默认的导入是在文档树里右键导入，然后选路径和文件，略显繁琐。这个插件支持直接把文件从系统文件夹里拖到思源文档树上。**

## 功能

- **文件、文件夹、压缩包都能拖**。支持一次拖多个 `.md`、整个文件夹或 `.zip`，子目录会变成子文档。
- **同名冲突可选处理方式**。跳过、加后缀、覆盖或追加，可以逐条选，也能一键对整批生效。
- **导入后能撤销**，回到导入前的状态。
- **附件跟着走**。正文引用的图片和其他本地文件一并上传，链接自动改写。
- **对 Obsidian 友好**。`![[图片.png]]` 转成图片链接，同一批导入的 `[[笔记]]` 转成思源块引用。

## 使用

1. 从资源管理器把文件拖到**文档树**上（不是编辑器）。
2. 拖到**笔记本行**：导入到它的根级；拖到**某篇文档**：作为它的子文档。拖在笔记本段的空白处也算根级。
3. 有同名时，在冲突卡片上选处理方式。
4. 结果卡片上可以打开第一篇、撤销本次导入、重试失败项、打开日志。

## 设置

**设置 → 集市 → 插件 → 拖拽导入（齿轮）**，或顶栏「插件」菜单里的插件条目。

| 设置项            | 默认  | 说明                              |
| -------------- | --- | ------------------------------- |
| 同名冲突默认处理       | 加后缀 | 冲突卡片的预选项                        |
| 撤销有效期（秒）       | 30  | 10–300；习惯先抽查再撤销可以调大             |
| 单篇大小上限（MB）     | 20  | 超过的跳过并列出                        |
| 保留文件夹结构        | 开   | 拖入文件夹时，外层文件夹本身也成一篇文档；关掉则内容直接落到拖放位置 |
| 剥离 frontmatter    | 开   | 去掉正文开头的 YAML 块；关掉则原样保留         |
| 移除重复的首行 H1     | 开   | 首行标题与文档名相同时删掉                   |
| 上传附件           | 开   | 关掉则保留原始相对路径（图片不显示）              |
| 转换 Obsidian 双链 | 开   | 同一批内 `[[笔记]]` → 块引用             |
| 恢复默认设置         | —   | 全部复位并立即保存                       |

## Markdown 兼容性

正文只动四处，其余原样交给思源解析：

| 会改动                         | 说明                              |
| --------------------------- | ------------------------------- |
| 开头的 YAML frontmatter        | 剥掉——思源不解析它，留着就是两条分隔线（设置里可关）     |
| 与文档名重复的首行 `# 标题`            | 删掉，避免树上和正文各一个标题（设置里可关）          |
| 指向本地文件的图片 / 附件              | 上传到 `assets/` 并改写链接；同一份文件一批只传一次 |
| 同一批内的 `[[笔记]]`、`[[笔记\|别名]]` | 转成思源块引用                         |

## 限制

- 只支持 Windows 桌面端；`.zip` 以外的压缩包（`.rar`、`.7z` 等）需要先转换。
- 不处理思源自己的导出包（`.sy.zip`）——请用**设置 → 导入 → SiYuan .sy.zip**。
- 空文件夹不建文档；`assets` / `images` / `img` / `attachments` / `static` 目录不建文档（里面的文件被引用时才上传）。
- 一次最多 2000 篇 Markdown；压缩包上限 200 MB（解压后 500 MB）。
- 撤销快照只在运行内存里。
- 双链只在本批一起导入的笔记里解析。
- 追加模式不动原有块，追加段里的 `[[链接]]` 保持原文。
- 开发与完整测试基于 3.8.8。

## 遇到问题

- 拖进去没反应：确认拖的是**文档树**（编辑器有自己的拖放逻辑），并确认插件已启用。
- 卡片上说「附件找不到」：正文引用的文件不在 md 旁边（也不在被拖的文件夹里）。链接会原样保留。
- 出错了：结果卡片上点**打开日志**，JSONL 在 `<工作空间>/data/storage/petal/siyuan-drag-import/logs/`。里面记了每个阶段和耗时。

## 开发

```bash
npm install
npm run dev          # 监听构建；在 .env 里设置 SIYUAN_WORKSPACE 可自动同步到工作区
npm run build        # 生产构建到 dist/
npm run verify       # 类型检查 + 构建 + 全部测试（e2e 需要思源在运行）
npm run test:offline # 不需要思源的测试
```

插件是 TypeScript，用 esbuild 打成 CommonJS 的 `index.js`。导入逻辑在 `src/import/`，拖放处理在 `src/drop/`，界面在 `src/ui/`，所有界面文案在 `src/i18n/messages.{zh,en}.ts`（有测试盯着：中文出现在这个目录之外就失败）。

行为约定见 `docs/DESIGN.md`，撤销背后的快照实验见 `docs/RESTORE-SPIKE.md`，开发里程碑见 `docs/MILESTONES.md`。
