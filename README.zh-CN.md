# 拖拽导入

**把 Markdown 文件、文件夹或 ZIP 压缩包从资源管理器直接拖到思源文档树上——层级原样还原成文档，正文里的图片和附件自动上传。**

不用复制粘贴，也不用「先导入、再慢慢补」。一个 200 篇的文件夹，拖一次就是一个 200 篇的文档目录。

![把文件夹拖进文档树：层级还原、附件上传、结果卡片可撤销](https://raw.githubusercontent.com/clock-05/siyuan-drag-import/main/preview.png)

## 什么时候用得上

- 从 Obsidian / Typora / Logseq 搬一整个库进来，不想一篇篇新建、一层层摆。
- 手上是一堆按项目分好目录的 md，想连目录一起搬进思源。
- 正文里的图片、PDF 散落在笔记旁边，不想导入完再一张张补。

只有一两篇 md 时，思源自带的「导入」就够用；这个插件省的是「一次几十上百篇、还要保住层级」的时间。

## 功能

- **文件、文件夹、压缩包**。可以一次拖任意多个 `.md` / `.markdown` / `.mdown` / `.mkd`、整个文件夹或 `.zip`。子目录会变成子文档；压缩包外面那层同名目录会被拆掉，不再多套一层。
- **同名冲突自己定**。逐条或一键选择：**跳过**、**加后缀**（`笔记 (2)`）、**覆盖**（保留文档 id 和子文档）、**追加**（在末尾接一段并注明来源）。
- **撤销就是回到拖进来之前**。30 秒内（可调）点一下：本批新建的删除，覆盖 / 追加的写回导入前的原文——动手前会先存快照。
- **附件顺手处理**。正文引用的图片和本地文件上传到 `assets/` 并改写链接。`![](...)`、`![[...]]`、`[pdf](files/a.pdf)`、`file:///C:/...`、带 `%20` 的路径都认；代码块里的写法不动。
- **对 Obsidian 友好**。`![[图片.png]]` 会转成图片或文件链接；同一批一起导入的 `[[笔记]]` 会转成思源块引用，点开即跳转。
- **进度不糊弄**。卡片显示篇数、当前文件和剩余时间，可以中途取消（已建好的保留，且仍能撤销）。
- **失败不拖累整批**。失败的篇目会列出原因，可以只重试这几篇；每批都有 JSONL 日志，卡片上直接打开。
- **中英双语界面**，跟随思源自身的语言设置。

## 安装

集市：**设置 → 集市 → 插件 → 拖拽导入 → 安装**。

手动：从最新 Release 下载 `package.zip`，解压到 `<工作空间>/data/plugins/siyuan-drag-import/`，重启思源。

只支持桌面端（Windows / macOS / Linux）——插件要读本地文件系统。最低思源版本 3.1.0；开发与完整测试基于 3.8.8。

## 使用

1. 从资源管理器把文件拖到**文档树**上（不是编辑器）。
2. 拖到**笔记本行**：导入到它的根级；拖到**某篇文档**：作为它的子文档。拖在笔记本段的空白处也算根级。
3. 有同名时，在冲突卡片上选处理方式。
4. 结果卡片上可以打开第一篇、撤销本次导入、重试失败项、打开日志。

拖到文档树的上/下边缘会自动滚动，想放进很深的层级不必先滚好。

### 结果卡片

| 状态 | 行为 |
| --- | --- |
| 完整卡片 | 计数、逐条失败原因，以及上面的几个按钮 |
| 4 秒后收缩成一行 | 只要还能撤销、或有失败项，就一直留着 |
| 零结果 | 5 秒后直接消失——「什么都没导入」不需要长期占位 |

## 正文会被怎么处理

| Markdown | 导入后 |
| --- | --- |
| YAML frontmatter | 剥掉（设置里可保留） |
| 与文档名重复的首行 `# 标题` | 删掉（可关） |
| UTF-8 / UTF-8 BOM / GBK | 自动识别；含 NUL 字节的按二进制拒绝 |
| `$行内$`、`$$块级$$` | 原样保留——思源自己能渲染 |
| `> [!note]` callout、`- [ ]` 任务、`==高亮==`、`[^1]` 脚注 | 原样保留——思源自己能渲染 |
| 本地图片 / 附件 | 上传并改写链接；同一份文件一批只传一次 |
| `[[笔记]]`、`[[笔记\|别名]]` | 目标在本批里时转成思源块引用 |
| `[[笔记#标题]]` | 原样保留（块引用指不到标题） |
| 代码块与行内代码 | 永远不改写 |

## 设置

**设置 → 集市 → 插件 → 拖拽导入（齿轮）**，或顶栏「插件」菜单里的插件条目。

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| 上传本地图片与附件 | 开 | 关掉则保留原始相对路径 |
| 剥离 frontmatter | 开 | 去掉正文开头的 YAML 块 |
| 移除重复的首行 H1 | 开 | 首行标题与文档名相同时删掉 |
| 转换 Obsidian 双链 | 开 | 同一批内 `[[笔记]]` → 块引用 |
| 同名冲突默认处理 | 加后缀 | 冲突卡片的预选项 |
| 单篇大小上限（MB） | 20 | 超过的跳过并列出 |
| 撤销有效期（秒） | 30 | 10–300；习惯先抽查再撤销可以调大 |
| 恢复默认设置 | — | 全部复位并立即保存 |

## 限制

- 只支持桌面端；`.zip` 以外的压缩包（`.rar`、`.7z` 等）需要先转换。
- 不处理思源自己的导出包（`.sy.zip`）——请用**设置 → 导入 → SiYuan .sy.zip**。
- 空文件夹不建文档；`assets` / `images` / `img` / `attachments` / `static` 目录不建文档（里面的文件被引用时才上传）。
- 一次最多 2000 篇 Markdown；压缩包上限 200 MB（解压后 500 MB）。
- 撤销快照只在内存里：重启思源后撤销窗口就结束了。
- 双链只在本批一起导入的笔记里解析。指向没一起拖的笔记时保留原文——去全库猜名字，猜错比不转更糟。
- 追加模式不动原有块，所以追加段里的 `[[链接]]` 保持原文。

## 遇到问题

- 拖进去没反应：确认拖的是**文档树**（编辑器有自己的拖放逻辑），并确认插件已启用。
- 卡片上说「附件找不到」：正文引用的文件不在 md 旁边（也不在被拖的文件夹里）。链接会原样保留，不会丢。
- 出错了：结果卡片上点**打开日志**，JSONL 在 `<工作空间>/data/storage/petal/siyuan-drag-import/logs/`。里面记了每个阶段和耗时，能一眼分清是插件的问题还是内核的问题。

## 开发

```bash
npm install
npm run dev          # 监听构建；在 .env 里设置 SIYUAN_WORKSPACE 可自动同步到工作区
npm run build        # 生产构建到 dist/
npm run verify       # 类型检查 + 构建 + 全部测试（e2e 需要思源在运行）
npm run test:offline # 不需要思源的测试
```

插件是 TypeScript，用 esbuild 打成 CommonJS 的 `index.js`。导入逻辑在 `src/import/`，拖放处理在 `src/drop/`，界面在 `src/ui/`，所有界面文案在 `src/i18n/messages.{zh,en}.ts`（有测试盯着：中文出现在这个目录之外就失败）。

行为约定见 `docs/DESIGN.md`，撤销背后的快照实验见 `docs/RESTORE-SPIKE.md`，开发里程碑见 `docs/MILESTONES.md`。
