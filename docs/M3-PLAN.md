# M3 压缩包导入

> 目标：把别人发来的 `.zip` 拖到文档树，解开的层级原样还原；坏包、加密包、路径穿越一律整包拒收。
> 前置：`DESIGN.md` v0.2 §4.3（压缩包处理）、§9（异常矩阵），M2 + 冲突策略已完成。

---

## 1. 范围

| 做 | 不做（留给后面） |
|---|---|
| `.zip` 解包（store / deflate） | `.rar` / `.7z`（提示转 zip） |
| 中文文件名：UTF-8 标志位 / GBK 兜底 | `.tar.gz` |
| 安全闸门：路径穿越、加密、条目数、体积 | 包内图片上传（M4） |
| 单顶层目录不套娃 / 多顶层按包名套一层 | 分卷压缩包 |
| 解压前校验，失败整包不落地 | zip64（>4GB） |
| 导入中「取消」 | 暂停/续传 |

## 2. 关键取舍

1. **不用 fflate 的 `unzipSync`**：它按 UTF-8 解文件名，Windows 自带压缩打的包（GBK、未置 bit 11）会先变乱码，原始字节丢了就没法救。改成自己读中央目录拿原始字节，`UTF-8 严格解 → 失败退 GBK`，同一处顺手做加密位 / 穿越 / 上限的闸门，再用 `inflateSync` 只解 md。
2. **只解 md**：图片附件 M4 才上传，没必要为它们占内存（500 MB 解压上限不必真的落到堆上）。
3. **整包先校验后落地**：解压/校验任何一步失败，一篇都不建。不做「能解多少算多少」。
4. **单顶层目录不套娃**：包内只有一个顶层目录时以它为导入根（`项目A/a.md` → `/项目A/a`）；多个顶层条目才用压缩包名包一层（`pack.zip` 里的 `a.md` → `/pack/a`）。

## 3. 安全闸门（解压前判定）

| 情况 | 判定 | 结果 |
|---|---|---|
| 条目路径含 `..` | 归一化后按段检查 | 整包拒收：「包含上级目录」 |
| 绝对路径 / 盘符开头 | `startsWith("/")` 或 `^[A-Za-z]:` | 整包拒收 |
| 加密条目 | 通用标志位 bit 0 | 整包拒收：「加密压缩包暂不支持」 |
| 条目数 > 5000 | EOCD 条目总数 | 整包拒收 |
| 解压后总量 > 500 MB | 中央目录累加 uncompressed size | 整包拒收 |
| 压缩包文件 > 200 MB | 读盘前按 size 判断 | 整包拒收 |
| 单篇 md > 20 MB | 条目 size | 该篇跳过，其余继续 |
| 压缩方式非 store/deflate | method 字段 | 整包拒收 |
| 数据截断 / inflate 失败 | 解压时抛错 | 整包拒收：「压缩包已损坏」 |

`.sy.zip` 在进入解包前就被拦下，提示走「设置 → 导入」。

## 4. 取消

- 进度卡片底部「取消导入」，点一次置灰为「正在取消…」（防重复触发）。
- 粒度 = 单篇（约 33ms），点下去最多再建一篇。
- 已建好的保留，结果卡片：「已取消导入 / 已导入 N 篇，其余未执行。」
- 冲突卡片上的「取消导入」是另一码事：那一刻还一篇都没建，文案是「没有创建任何文档。」

## 7. 手动验收

1. Windows 右键「压缩为 ZIP」打的中文文件夹 → 拖进来，文件名不乱码、层级正确。
2. 包内只有一层目录 → 树里不出现「包名/目录名」双层套娃。
3. 包里是散的 `a.md` + `img/` → 建 `/包名/a`，图片计入「1 个图片/附件」。
4. 加密 zip / 手改坏的 zip → 卡片报错，文档树零新增。
5. 100 篇以上的 zip → 先「正在读取…」，再「正在导入 N 篇」，中途点取消 → 只保留已导入的。
6. `.rar` → 提示先转 zip；`.sy.zip` → 提示走设置里的导入。

## 8. 已知缺口

- `.tar.gz` 没做：DESIGN §15 曾建议支持，但需要额外处理 pax 长文件名，先把 zip 做稳。
- 包内图片不会随正文上传，链接仍是死链 —— M4。
- zip64（条目 > 4GB 或总数 > 65535）不支持，会以「条目过多 / 目录损坏」拒收。
- 解压是同步的：200 MB 的包会让界面卡 1–2 秒（已先用「正在读取」卡片占位，但没有做成 Worker）。
