## 2. 任务 A：修「pdf 链接前有其他字就失效」

### A.1 已复现的失败形状（今天实测，`src/import/assets.ts` 的 `LINK_PATTERN`）

| 输入 | 结果 |
|---|---|
| `[规格书](files/讲义.pdf)` | ✅ 上传并改写 |
| `详见[规格书](files/讲义.pdf)` | ✅ |
| `**重要**：[规格书](…)`、`- [规格书](…)`、`> [规格书](…)`、表格内 | ✅ |
| **`[规格书[2024]](files/讲义.pdf)`** | ❌ 链接文字里有方括号 → 整条不匹配，静默跳过 |
| **`[规格书](files/讲义(1).pdf)`** | ❌ 路径带圆括号（Windows 重名文件极常见）→ 不匹配 |
| **`[规格书](files/讲义 2024.pdf)`** | ❌ 路径带空格 → 不匹配，且**不计数** |
| **`[规格书](<files/讲义 2024.pdf>)`** | ❌ 尖括号包裹也没接住（`resolveRef` 去尖括号了，但正则先失配） |
| **`下载![规格书](files/讲义.pdf)`** | ⚠️ 被当成图片语法 → 产出 `![](assets/x.pdf)` 坏图 |

> 用户原话「pdf 链接前有其他字好像就失效了」。上表里最可能是**链接文字里有方括号**
> （Zotero 复制的文献名 `[Zwonek 2012] …` 当前就长这样）。开工第一件事：**请用户发那一行原文**，
> 用它当回归用例；同时上表 5 条一并修掉。

### A.2 根因

`assets.ts` 用一条正则解析 Markdown 链接：

```ts
const LINK_PATTERN = /(?<!!)\[([^\]]*)\]\(\s*(<[^>]*>|[^)\s]+)((?:\s+(?:"[^"]*"|'[^']*'|\([^)]*\)))?\s*)\)/g;
```

三个硬伤：`[^\]]*` 不认链接文字里的 `]`；`[^)\s]+` 不认路径里的空格与括号；`(?<!!)` 只能挡住图片，
挡不住「感叹号紧贴的普通链接」被图片那一遍先吃掉。

### A.3 修法（推荐）

**不要再加正则打补丁**，换成一遍字符扫描器（`src/import/scanLinks.ts`，纯函数、可单测）：

1. 从左到右扫，遇到 `[` 记录起点，按**方括号配对深度**找配对的 `]`（支持 `[a[2024]]`），
   `\` 转义时跳过下一个字符。
2. 紧跟 `]` 的若是 `(`，解析 destination：
   - 以 `<` 开头 → 读到 `>`，中间允许空格；
   - 否则读到**配对**的 `)`，路径里的 `(` `)` 按深度计入；同时允许末尾有 `"title"` / `'title'` / `(title)`。
3. 紧跟在 `]` 前面（下标 -1）若是 `!` → 图片；否则普通链接。
   **图片目标若不是图片扩展名（.pdf/.docx…）→ 落成普通链接**，修掉 A.1 最后一条。
4. 保留原「只换命中片段、其余原样」的写法，避免破坏代码块/引用块。

顺序仍是：图片 → 普通链接 → Obsidian 嵌入（嵌入最后，不会被前两遍重复处理）。

**必测**（`test/images.mjs` 追加）：上表 8 条 + `[文字](a.pdf "标题")`、`[文字](<a b.pdf>)`、
`![图](a.png)` 紧贴 `[pdf](b.pdf)`、代码块里的 `[x](a.pdf)` 不动（可选，若要支持需跳过 ``` 围栏）。

### A.4 验收

- 用户那行原文 + 上表 8 条全部通过，且导入后链接可点、文件进 `assets/`。
- 卡片统计仍对：`已上传 N 个附件（.pdf）` 不多不少。
- 全量测试不退化（当前 338）。

## 3. 任务 B（已否决，2026-10-25 用户决定不做）

> **结论：整块不做。** spike 已证明「从思源拖文档到资源管理器」在本 App 里没有技术通路
> （Electron 没有 `DownloadURL`），唯一能落地的「命令式导出」没有拖拽体验，用户评估后认为不值。
> 下面的内容只作记录，**不要再实现**。

### B.1 目标行为

- 在文档树上按住一篇文档拖到 Windows 资源管理器的文件夹 → 落成 **`标题.md`**。
- 设置里可把默认导出格式改成思源支持的其他类型；多选时需要明确「一次一个」还是「打包 zip」。

### B.2 必须先做的可行性验证（**先 spike，再动手**）

> **2026-10-25 已验完，结论见下，别重做。**
>
> | # | 结论 | 依据 |
> |---|---|---|
> | B2-1 | ❌ **`DownloadURL` 在 Electron 里没有实现** | `grep -a -o -i downloadurl SiYuan.exe` 只命中 `setSpellCheckerDictionaryDownloadURL`（拼写词典），拖拽那个 MIME 一次都没有。它是 Chrome 浏览器层的功能（`chrome/browser/download/drag_download_util.cc`），Electron 只给主进程 `webContents.startDrag`，渲染进程够不到 |
> | B2-2 | ❌ 同上（且 Chromium 一次 drag 只带一个原生文件项） | 同 B2-1 |
> | B2-3 | — 不适用（没有拖出通道） | — |
> | B2-4 | ✅ 见下方「导出 API 实测」 | 直接打 6806 接口验的 |
>
> **导出 API 实测（SiYuan 3.8.8）**
>
> - `exportMdContent {id}` → `{hPath, content}`，content 就是 markdown 文本，**自带 YAML frontmatter**。做 md 导出首选。
> - `exportMd {id}` → `{name, zip:"/export/<标题>.md.zip"}`，`GET` 该路径可下（200，`application/x-zip-compressed`），
>   包里是 `<标题>.md`，**不含图片**。
> - `exportMdHTML {id}` → `{id, name, content:"<h1 id=…>…"}`。
> - `exportDocx {id, savePath, removeAssets, merge}` → `savePath` 是**目录**（内核自动建），文件落在
>   `<savePath>/<标题>.docx`，返回 `{path}`；三个参数缺一个就报 `Field […] is required`。
>
> **因此 B 只剩一条路：命令式导出（B.4-3）** —— 菜单/命令面板「导出到…」，
> md 用 `exportMdContent` + `fs.writeFileSync`，其他格式传 `savePath` 让内核自己写。
> B.4-1（blob + DownloadURL）和 B.4-2（uri-list）随之作废，别试。

| # | 要验证的事 | 怎么验 | 失败怎么办 |
|---|---|---|---|
| B2-1 | Electron 里 `dataTransfer.setData("DownloadURL", "text/markdown:名.md:data:text/markdown;base64,…")` 能否真在 Explorer 落文件 | 插件里加最小监听，拖到桌面看结果 | 试 `blob:` URL；再不行见 B.4 降级 |
| B2-2 | 多文件拖出是否可能 | 同上，塞两个 item | 基本不行（Chromium 只认一个），多选取「打包 zip」 |
| B2-3 | 中文文件名、空格、方括号是否正常 | 用 `带 空格[1].md` 试 | 记下来，必要时改写文件名 |
| B2-4 | 内核导出 API 的返回结构 | 见下 | 只做 md |

**已确认的情报**（今天从安装目录里查到，省得重查）：

- 思源前端**没有任何** `DownloadURL` / `startDrag` 用法 → 拖出功能在本 App 里没有先例，B2-1 必须实测。
- 内核导出 API 名单（`resources/kernel/SiYuan-Kernel.exe` 里 grep 到的）：
  `exportMdContent`、`exportMd`、`exportMds`、`exportSY`、`exportHTML`、`exportMdHTML`、`exportDocx`、
  `exportEPUB`、`exportODT`、`exportAsciiDoc`、`exportOPML`、`exportReStructuredText`、`exportMediaWiki`、
  `exportData`、`exportNotebookMd`、`exportNotebookSY`。
  - `exportMdContent` 最可能直接返回 markdown 文本（`{hPath, content}`），优先用它做 md 导出。
  - 其余多数会生成 zip 落在工作区 temp，返回 `data.path`；要用 `fflate` 解包取目标文件。
  - 单文档导出**不含图片**：图片链接仍是 `assets/xxx.png`，导出文件旁边没有图 —— MVP 接受并在卡片/提示里说明。

### B.3 实现提纲

| 文件 | 改动 |
|---|---|
| `src/export/dragOut.ts`（新） | 在文档树监听 `dragstart`（捕获阶段），拿 `data-node-id` → 查标题 → 取内容 → `setData("DownloadURL", …)` |
| `src/export/api.ts`（新） | `exportMdContent(id)` / `exportSingle(id, format)` 薄封装（超时、错误归一） |
| `src/settings.ts` | 新增「拖出格式」下拉：`Markdown（.md）` 默认，其余按 B2-4 实测结果填 |
| `src/index.ts` | 挂载/卸载 dragOut；设置项接线 |

要点：
- 只在**拖到应用外**才写 DownloadURL —— `dragstart` 阶段判断不了目标，所以一律设置；
  思源内部拖动会忽略这个 item，但**必须实测**「拖文档到另一个笔记本」是否被影响。
- 不要碰现有的 `DropController`（那是拖入），两者互不干扰。
- 一次拖多篇：MVP 只导出**第一层选中的那一篇**，并在拖拽后提示「一次拖一篇」；第二版再做 zip。

### B.4 若 DownloadURL 不可用（降级方案，按顺序试）

1. `blob:` URL + `DownloadURL`。
2. `text/uri-list` + `file://` 指向**已经写到磁盘的临时文件**（在设置里指定一个「导出目录」）。
3. 改为命令式：右键/命令面板「导出到上次目录」，用 `fs` 直接写文件到设置里的目录（无拖拽，但一定可用）。

### B.5 分两步交付

- **B-1（先做）**：单文档拖出 `.md`；B2-1 通过即交付，跑不通就先做 B.4-3 的命令式兜底。
- **B-2（有余力）**：多选打包 zip；设置里补其他格式（按实测可用的填，不硬凑）。

## 4. 任务 C：去掉顶栏齿轮，设置入口并入思源自己的插件菜单

### C.1 已确认的机制（今天从 `resources/stage/build/app/common.*.js` 里查到）

思源 `Plugin` 基类自带：

```js
openSetting() {
  if (destroyed || !this.setting) return;
  // 移动端走 openPluginSetting，桌面端：
  this.setting.open(this.displayName || this.name);
}
```

而顶栏「插件」菜单（`menuPluginTopBar`）会**遍历所有已启用插件**，给每个插件加一条
`{ icon: "iconSettings", label: displayName, click: () => plugin.openSetting() }`——
**这条不依赖插件有没有顶栏图标**。集市「已下载」里的齿轮走的也是 `openSetting()`。

### C.2 改动点

1. `src/index.ts`：删掉 `this.addTopBar({ icon: "iconSettings", … })`。
2. 把 `createSettingPanel(...)` 的返回值存到 **`this.setting`**（基类字段名，必须叫 `setting`）。
3. `src/types.d.ts`：`Plugin` 补 `setting?: any`（已有 `addTopBar` 之类，一并清理没用的声明）。
4. 可选：加一个 `addCommand`（`langKey: "openSetting"`）给快捷键党，i18n 里补文案。

### C.3 验收

- 顶栏不再有齿轮；拖拽导入功能完全不受影响（重启用 3 个基本用例验）。
- 点思源顶栏「插件」菜单 → 列表里有「拖拽导入」→ 点开就是原来的六项设置。
- 集市「已下载」里该插件也有设置入口（同一个 `openSetting`）。
- 卸载后无残留（`onunload` 不需要额外清理，因为我们没再注册顶栏元素）。
