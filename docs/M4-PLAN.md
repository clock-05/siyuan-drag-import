# M4 图片、追加、撤销、设置

> 目标：把「导入完还能看」补上（图片入库）、把冲突处理补全（追加）、把误操作兜住（撤销），并给用户可见的开关。
> 前置：M1–M3 + 冲突策略已完成；DESIGN §6.5 / §7.2 / §8.3 / §10。

---

## 1. 范围

| 做 | 不做 |
|---|---|
| 本地图片上传 + 链接重写（磁盘 / 压缩包内） | 外链图片下载（v2） |
| `![[a.png]]` Obsidian 嵌入转换 | 图片去重（内核按内容自行复用，不承诺） |
| 冲突策略补「追加」 | 撤销覆盖/追加（无旧内容快照） |
| 撤销本批「新建」（两步确认 + 5 分钟） | 跨批次撤销 |
| 设置面板 6 项 | 按笔记本覆写设置 |

## 2. 关键取舍

1. **链接只信 `succMap`**：M0 已确认内核返回 `<原名>-<时间戳>-<id>.png`，同内容再传可能复用也可能新建，自己拼路径必错。
2. **相对路径按 md 所在目录解析**；压缩包里的 md 按包内路径解析，图片直接从 ZIP 条目取字节，不需要先解压到磁盘。
3. **同批同图只传一次**：cache key 是磁盘绝对路径 / 包内条目路径；失败也缓存，避免一张坏图反复重试。
4. **追加用 `appendBlock`**，不是 `updateBlock`：「接在原文末尾」不能碰原有块，文档 id 也不该变。
5. **撤销只删自己建的**：`scanPlan` 记录导入前不存在的目录（`autoDirs`），撤销时删最上层那个目录（连带子文档），再删不在这些目录下的新建文档；**复用的父文档一个都不碰**。
6. **撤销两步确认**：第一下变「确认撤销 N 篇？」，3 秒内再点才执行——删库操作不该一击生效。
7. **覆盖/追加不可撤销**：没有保存旧正文；卡片上不提供这两类文档的撤销入口。

## 6. 手动验收

1. 拖一个含 `img/a.png` 的 md（或文件夹）→ 文档里图片能显示，链接是 `assets/...`；卡片有一行「已上传 1 个附件（.png）」。
2. 关掉「上传本地图片与附件」再拖 → 链接仍是 `img/a.png`（图片不显示，符合预期）。
3. 拖一个图片缺失的 md → 卡片写「1 张找不到」，正文其它内容正常导入。
4. 冲突选「追加」→ 原文档末尾多一段带 `---` 和「以下内容来自 xxx.md」的内容，原内容还在。
5. 导入一个文件夹后点「撤销本次导入」→ 第一下变「确认撤销 N 篇？」，再点 → 整棵目录消失，其它文档不受影响。
6. 撤销按钮等 5 分钟（或在设置里改成 1 分钟）→ 变成「撤销已过期」且不可点。
7. 顶栏齿轮 → 六个设置项可改，改完重启/重载插件仍生效。
8. 正文写 `[规格书](docs/规格书.pdf)`，连同 `docs/` 一起拖进来 → 链接变成 `assets/…pdf`，点击能在思源内打开 PDF；卡片写「已上传 1 个附件（.pdf）」。
9. Obsidian 里的 `![[[Zwonek 2012] 文献.pdf]]`（文件名带方括号）→ 导入后变成可点链接，不残留 `![[`；卡片写「已上传 1 个附件（.pdf）」，后缀看得见。

## 7. 真机反馈修复（0.5.1）

用户拿 Obsidian 库试：`未命名.md` 里是 `![[Pasted image 20261024211413.png]]`（文件名带空格），
结果图片没上传、链接也没改写。

- **根因**：旧逻辑先把 `![[...]]` 转成 `![](Pasted image ....png)` 再统一匹配标准图片语法；
  文件名里的空格让标准语法正则匹配失败，于是「既没上传、又把原文改成了坏语法」。
- **修复**：嵌入语法单独一遍处理——解析成功才替换成 `![alt](assets/...)`，失败就**保留原样的 `![[]]`**；`|300` 这类尺寸参数不再当成 alt 文案。
- **顺带**：只写文件名时，会去同级的 `assets/attachments/img/images/static`（磁盘）或包内同名条目（zip）里再找一遍；单独拖一张图片不再说「没有可导入的文件」，改成「图片不能单独导入」并给出正确用法。
- **验证**：`test/images.mjs` 增加 6 项（带空格嵌入、尺寸参数、缺失保留）；真机 e2e 用一份 Obsidian 形态的库复现，确认链接变成 `assets/...` 且不再残留 `![[]]`。
- **另测**：`getBlockDOM` 确认 Lute 对 `![](assets/a b.png)`（原始空格）、`%20`、`<...>` 三种写法都能解析成图片节点，所以最终链接不必编码空格。

## 8. 交互打磨（0.5.2）

- 只有 1 篇同名时：标题改成「这篇文档已存在」，并**隐藏「全部跳过/全部加后缀/全部覆盖/全部追加」**（只有一条，批量按钮没意义），副标题改成「选一种处理方式」。
- 图片提示改成每段自带主语：「1 张图片找不到，图片链接保持原样」。原先前半段没出现「图片」二字，只丢一张时读起来像在说别的东西。

## 9. 附件链接（0.6.0）

用户问「pdf 是不是同等待遇」，确认后让插件把正文里指向本地文件的**普通链接**也一并上传。

| 做 | 不做 |
|---|---|
| `[规格书](docs/规格书.pdf)` → 上传 → `assets/…pdf` | 外链下载（`https://…pdf` 原样保留） |
| 与图片共用上传通道与缓存（同一文件只传一次） | 解析 md 里指向**其它 md** 的链接（仍按 §6.6 的 v2 计划） |
| 统计拆 `images` / `files`，卡片分别措辞 | 新增设置项（沿用「上传本地图片」开关） |

**关键取舍**

1. **不新增开关**：用户心里的「上传本地资源」是一件���，图片和附件分两个开关只会让人困惑。关掉时两者一起保留原路径。
2. **`isLocalRef` 白名单式排除**：`http(s)://`、`//`、`mailto:`、`tel:`、`siyuan://`、`#`、`assets/` 全部不动。宁可少改写，也不要把外链改成坏链接。
3. **嵌入与普通链接分两遍扫**：`![]()` 先处理，再处理 `[]()`，靠一个 `(?<!!)` 断言避免同一条 `![]()` 被当成普通链接二次处理；同一文件的 `hits` 去重，避免重复上传。
4. **50 MB 上限**：附件比图片大得多，但没有理由把 2 GB 的安装包塞进 `assets/`。

**实现落点**：`src/import/assets.ts` 的 `rewriteAssets`（`AssetStats { images, files }`）、`src/import/executor.ts` 的返回值、`src/ui/result.ts` 的 `describeAssets`。

## 10. 真机反馈（0.6.1）：Obsidian 的 PDF 嵌入

用户从 Obsidian 库拖一篇带 PDF 的笔记，导入后正文原样留着：

```
![[[Zwonek 2012] GEOMETRIC PROPERTIES OF THE TETRABLOCK.pdf]]
```

**两个问题叠在一起**

1. 旧的正则 `!\[\[([^\]|#]+)…` 不允许 `]` 出现在文件名里。Zotero 导出的文献名恰恰带方括号，
   于是整条**根本没匹配上**——pdf 没上传、原文没动、卡片也没有任何提示。
2. 即使匹配上，旧逻辑也一律按图片处理（`![](assets/x.pdf)`）。思源把 pdf 当图片渲染只会得到坏图。

**修法**

| 改动 | 说明 |
|---|---|
| `EMBED_PATTERN` 改成 `!\[\[([^\n]+?)\]\]` | 惰性吃到最近的 `]]`，文件名里可以有 `]`；`#子路径` 和 `\|别名` 在解析阶段再拆 |
| 嵌入按扩展名分流 | 图片 → `![alt](assets/…)`；pdf/docx 等 → `[文件名](assets/…)`，点开由思源内置阅读器打开 |
| 链接文字里的 `[` `]` 转义 | 产出 `[\[Zwonek 2012\] ….pdf](assets/…)`，真机 `getBlockDOM` 确认渲染成 `<span data-type="a">` |
| 无扩展名的嵌入跳过 | `![[另一篇笔记]]` 是笔记内嵌，不是文件，不动也不计数 |
| 只写文件名时在整棵被拖文件夹里找 | Obsidian 的附件目录常叫「附件」，不在固定白名单里；按根目录建一次索引（深度 3、4000 个文件上限） |
| 处理顺序改为「图片 → 链接 → 嵌入」 | 嵌入最后落地，产出的语法不会被前两遍当成新引用重复处理 |

**顺带修措辞（0.6.1 的第一版，0.6.2 又改了一次，见下）**：卡片不再写「附件」。按扩展名说「1 个 PDF」「2 个 Word」，
多类型合并成「3 个文件（PDF、Word）」；文件夹汇总行也带上类型（「3 个图片/附件（PNG、PDF）」）。映射集中在 `src/labels.ts`。

**教训**：用「排除某个字符」的字符集写语法正则，一定会被真实文件名打破。文件名里 `[ ] # | & 空格` 全都合法。

**另一条**：Obsidian 的 `![[a.pdf]]` 普遍只写文件名，附件目录是用户自定的（默认 `assets/`，中文库里常叫「附件」）。
只认固定目录名会漏——现在会按被拖的根目录建一次索引兜底，深度与数量都有上限，不会在大库上卡住。

## 11. 措辞再改（0.6.2）：统一成「附件 + 后缀」

用户看完 0.6.1 的卡片说「把图片也归到附件类，统一全说成文件后缀名」，于是把「图片说张 / 文件说 PDF」两套口径合并：

| 之前（0.6.1） | 现在（0.6.2） |
|---|---|
| 已上传 3 张图片、2 个 PDF | 已上传 5 个附件（.png、.pdf） |
| 1 个 PDF 找不到，链接保持原样 | 1 个附件找不到（.pdf），链接保持原样 |
| 3 个图片/附件（PNG、PDF） | 3 个图片/附件（.png、.pdf） |

- `AssetStats.kinds` 改为**连图片一起统计**，data URI 上传也计入；没有扩展名的记「无后缀」。
- 后缀按数量降序、超过 3 种用「等」收（`summarizeExts`）。
- 「图片链接保持原样」的尾巴取消，统一「链接保持原样」。

## 12. 已知缺口

- 覆盖/追加不保存旧内容，撤销无法还原。
- 外链图片不下载（`![](https://...)` 原样保留）。
- 图片上传是串行的：100 张图约 100 次请求，没有并发池。
- 设置面板只有全局一份，不分笔记本。
