# 同名冲突策略（提前到 M2 之后做）

> 起因：M2 验收第 3 条「再拖一次同一文件夹」原本是**静默加 ` (2)`**，用户觉得不舒服——
> 父文档复用没问题，但同名文件怎么处理应该由自己决定。
> 设计原文在 `DESIGN.md` §7.2（原本排在 M4），这次提前实现其中的「跳过 / 加后缀 / 覆盖」。

---

## 1. 交互

拖入后先扫描，发现同名才停下来问；没有冲突时完全不打扰。

```
┌──────────────────────────────────┐
│ 有 3 篇同名                    × │
│ 导入到「知识类」，逐条选或一键全部   │
│ 笔记            [跳过][加后缀][覆盖] │
│ spec            [跳过][加后缀][覆盖] │
│ 另有 1 项，默认「加后缀」…          │
│ ⚠ 覆盖会清空已有正文（子文档保留），可撤销还原 │
│ [全部跳过][全部加后缀][全部覆盖]      │
│ [取消导入]            [开始导入]   │
└──────────────────────────────────┘
```

- 默认全选「加后缀」= 原来的行为，不想选也能直接点开始
- 逐条改某一行的选择；「全部 X」一次改完
- 只有出现「覆盖」时才显示风险提示
- 最多列 5 行，其余归到「另有 N 项」，全部按钮作用于所有项
- 关闭 / 取消导入 = **一篇都不建**，不是「默认加后缀偷偷跑完」

## 2. 三种选择的语义

| 选择 | 行为 | 代价 |
|---|---|---|
| 跳过 | 保留原文档，本次不导入该篇 | 卡片里计入「跳过：同名，已跳过」 |
| 加后缀 | 建 `名称 (2)`、`(3)`…，原文档不动 | 与 M1/M2 旧行为一致 |
| 覆盖 | **原地替换已有文档的正文**，id 不变、子文档保留 | 正文被清空重写；导入前留 kramdown 快照，撤销时写回 |

覆盖**不是**「删了重建」：删除父文档会连带删掉所有子文档（M0 结论），所以改走
`/api/block/updateBlock {id, dataType:"markdown", data}`。真机探针（`research/m3/probe-overwrite.mjs`）确认：

- 文档 id 不变
- 子文档仍在
- 标题 / 列表 / 代码块等块结构能正常重建
- 传空字符串会留一个空段落，文档不会消失

## 3. 批次内重名

同一批里两个同名文件（例如 `a/笔记.md` 与 `b/笔记.md` 落到同一层）**不弹卡片**，自动加后缀。
它不是「和已有内容冲突」，弹窗只会让人困惑。
